# Shipping HOT 人工剪藏（本地离线首片）

当前批准的独立合成包及手动交接见[测试构建说明](../../tools/clip-synthetic/README.md)和[当前状态](../../docs/status.md)。仅显式测试包额外接受唯一原创本地URL，普通包继续遵守下方HTTPS限制。用户自行加载/点击/保存，实际Chrome验收尚未通过。

这是可审查的本地扩展包；用户手动加载测试不等于完整验收。当前新SHA的实际Chrome交互与GUI/S7以状态文档证据为准，不将离线通过写成GUI已通过。完整合同见[ADR-010](../../docs/adr/ADR-010-local-manual-clip.md)，当前证据见[状态](../../docs/status.md)。

本地构建：`pnpm build:clipper`，输出 `<repo>/.tmp/clipper-package`。固定公开扩展ID `jihkanbaffodclncabodmbahbbgkjoad`；接收地址严格为 `http://127.0.0.1:5173/feed`。这不会启动或配置该服务。入口不匹配时拒绝；不要通过修改全局CORS/Origin、扫描端口或删除Origin来接通。需要其他端口时先审查并同步修改共享常量和Manifest、重新构建/验收。

只有主会话批准安装后，才可由用户加载该目录并授予 `activeTab`、`scripting`、`storage`。本轮不自动操作浏览器。正常流程：

1. 用户在自己选定的HTTPS网页点击插件，选择当前文章、选区或仅标题链接，在纯文本预览中编辑。
2. 剪藏流程无需填写姓名；系统自动记录保存时间和未识别人工操作（未经身份认证），兼容旧记录自填姓名。权利依据默认未知，范围默认元数据；正文需明确选择本人原创或已获许可、填写依据及全文/摘录范围。摘录上限280字符。未知权利时需明确点击“移除正文”后发送，不静默丢弃。
3. 点击“送到Shipping HOT预览”。插件仅建立120秒的一次性内存草稿，打开精确本机地址；URLfragment只含随机nonce，正文不在URL中。
4. 系统领取到内存表单，展示实际URL、原日期、提取时间及用户声明。用户核对/编辑后显式点击保存；成功后可以在已有资讯记录中打开正文和旧版本。

纯文本保留结构分隔：段落/块之间空行，`br`与列表项换行，表格单元格用制表符、行用换行。selection和article使用同一转换；这是文本分隔，不是HTML预览。修复后的新提取不会改写已有版本或自动重抓原页。

`PRE`子树的空格、制表符及换行（含行内元素）在纯文本转换中原样保留，外围普通段落的空白整理不会穿透进去。article模式此前的Defuddle代码块处理仍会展开制表符、修剪/整理空白；需要原选区空白时使用selection，预览确认后再保存。

领取失败、过期或刷新导致草稿丢失时，从插件重新发送。保存响应不确定时，原表单保持草稿并复用提交编号；编辑后再次保存使用新编号。草稿只允许一个，发送新草稿会替代旧待领草稿。没有云同步或持久配对凭据。

“人工剪藏资料”未经独立核验，不是官方预警、来源自动抓取成功、港口影响确认或R2通过证据。用户声明也不授予自动抓取、转发或模型使用权限。原自动产品许可继续由服务器决定。

此首片不支持HTTP、IP地址、非标准端口、含敏感参数的URL、登录/表单字段、跨frame选区、闭合shadow DOM和正文资源补取。提取失败时明确提示使用选区或元数据；不自动调用模型或联网补救。未保存正文在弹窗关闭后丢失；已存正文仍受原版本/审计机制管理。

源码复用及许可：[清单](../../third_party/obsidian-clipper/README.md)。仅Defuddle0.19.2用于浏览器DOM路径，后端Readability不变。
