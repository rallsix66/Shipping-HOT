# R2-2 source-specific CA support - 2026-10-13

Authorized slice: application support and offline validation under the 9/29 R2-2 plan, relayed by the parent review conversation. No real source configuration/activation or system root installation.

- Existing secureFetchArticle accepts optional sourceCa `{ sourceId, hostname, certificatePem }`. The public PEM must contain one parseable X509 CA certificate, at most 64 KiB. Source ID must match the policy; hostname must be an exact policy host, not a wildcard, URL or port. Missing/bad fields, unknown keys and HTTP with an explicit CA fail before DNS with source_ca_invalid; no PEM is included in error messages.
- Configuration is snapshotted before asynchronous work. Every HTTPS hop independently selects the CA only when host/source binding applies. Same host retains its configured CA; another allowed redirect host uses system trust. A host/address outside the security policy remains blocked. The optional CA is not a global trust registry, and no file lookup or secret/schema field is introduced.
- Bound HTTPS requests use the configured trust anchor; absent CA omits Node's ca option and keeps its normal system/default trust. rejectUnauthorized is explicitly true on every HTTPS request; normal checkServerIdentity/SNI/URL hostname, validated-address lookup, protocol/private-address/redirect/timeout/byte-limit protections remain in place. There is no retry using weaker trust.
- Intel collector seeds and existing Feed list source definitions pass the optional config to the same fetch chain. Current production seeds/definitions have no configured CA. Other independent provider fetchers are outside this slice; this is not a claim of project-wide CA support.
- Test fixture is a generated public self-signed CA PEM. Its disposable key stays in ignored .tmp and is not committed. Node http/https request is mocked in the existing offline transport fixture: no socket or real self-signed site is contacted. Certificate parsing/signature and request options are tested; actual TLS handshake/current upstream acceptance remains NOT_RUN.

Acceptance: A source does not affect B (including same host); exact host/redirect scope, mid-flight config mutation, absent vs missing/bad config, TLS failure without fallback, old intel/Feed data retention, DNS pinning/private redirect/HTTPS downgrade/response cap, plus full local gate. Code/evidence SHA and closeout live in docs/status.md. Schema remains 27; no migration, production switch, registry activation, live/paid/R3/merge/deploy work.
