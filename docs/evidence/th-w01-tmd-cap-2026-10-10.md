# TH-W01 TMD CAP 官方预警（R1.5，2026-10-10）

依据：信源目录 TH-W01（`https://www.tmd.go.th/en/api/xml/CAP`，「泰国气象预警只用这个源」）；9/29 方案 §4.8 官方预警。

## 1. 官方入口返回什么（2026-10-10 约 13:33 UTC+8，只读）

- 入口 `https://www.tmd.go.th/en/api/xml/CAP` 返回 HTTP 200 `text/xml`。内容是 **RSS 2.0 索引**（7 个 item），不是 CAP 正文。
- 每个 item 的 `<link>` 指向一份 **CAP 1.2 正文**（`https://www.tmd.go.th/uploads/CAP/en/CAPTMD<时间>_2.xml`），7 份都返回 HTTP 200。
- CAP 正文的字段：`identifier`（例如 `TMD20261010062912_2-en`）、`sender=TMD`、`sent`、`status=Actual`、`msgType`（Alert 或 Update）、`references`（例如 `TMD,TMD20261009050353_2,2026-10-09T04:58:00+07:00`；注意引用里的标识**没有** `-en` 后缀），以及 `info` 下的 `event`/`severity`（Severe 或 Extreme）/`effective`/`expires`/`area`。`area` 里有 `areaDesc`（自由文本）、`polygon`，以及 **`geocode` ISO3166-2**（如 TH-21）。
- 脱敏样本：`docs/evidence/th-w01-tmd-cap-2026-10-10/`。内容和测试夹具 `server/providers/__fixtures__/tmd-cap-2026-10-10/` 相同，只删掉了 `<polygon>` 坐标串（保留顶点数注释），其他字段原样保留。

## 2. 实现

- **新增 `server/providers/cap-alerts.ts`：**
  - 只采用 `status=Actual`，Test/Exercise/System/Draft 一律忽略。
  - `msgType` 只接受 Alert/Update/Cancel，Ack/Error 忽略。
  - Update 和 Cancel 会让 `references` 里引用的消息全部失效。匹配时忽略语言后缀，`-en` 与无后缀视为同一条。
  - 生命周期：`sent` 和可解析的 `expires` 都有才算 active；`expires ≤ now` 为 expired；`expires` 缺失或无法解析为 unknown，并且不进入事件。
  - 严重度：Extreme→critical，Severe→warning，Moderate→watch，Minor、Unknown 或缺失→info。
  - 覆盖区域：只取本国的 ISO3166-2 geocode，写入 `alertRegion`（如 `TH-21, TH-22`）。外国代码丢弃；没有 geocode 时不写区域、不关联港口。`areaDesc` 自由文本不用于判断。
  - 港口关联：通过结构化映射 `capSubdivisionPorts`，目前只有 `TH-20`（春武里府）→ `port-laem-chabang`。
- **`weather-alerts.ts`：**
  - 删除原约 L261 的 `capInfoAlerts`（它无条件写 `active: true`）。`parseWeatherAlertCap` 改为按 CAP 字段推导生命周期。
  - TMD 源的 `format` 从 `rss` 改为 `cap_index`，并加上 `countryCode: "TH"`：先取索引，再逐个取 CAP 正文；任何一份正文请求失败，整次运行按失败处理，不编造预警。
  - 之前已入库的预警如果被本次的 Update 或 Cancel 引用，会被标记为 expired，并且不再进入事件。
  - **`enabled` 和 `liveStatus` 都没有改**（仍是 `enabled: true / verified_live`），没有动生产开关。
  - 注意：生产同步路径会因此多发最多 20 个 CAP 正文请求。只在同步任务中发生，GET 请求不会触发。
- **测试**（`server/providers/tmd-cap.test.ts`），**范围：解析器 → provider → SQLite（同步任务）→ 面板服务层；不是 HTTP 路由，也不是浏览器**：
  - 实拍样本：入口形态；Update 链让 3 条旧消息失效；剩下 4 条中，2 条 active（Severe→warning、Extreme→critical）、2 条 expired；都不关联 Laem Chabang。
  - 合成用例（文件里已标明 SYNTHETIC）：Test/Exercise/System/Draft/缺失状态被忽略；Ack/Error 被忽略；Update 取代旧消息；Cancel 移除旧消息（同批，以及跨两次运行时已入库的预警）；过期；缺 `expires`；`expires` 无法解析；没有区域；跨国代码；混合代码只保留本国；严重度映射。
  - 存储到面板：TH-20 的 active 预警会出现在 `officialAlerts` 和 WR-O01 潜在影响里；Test 消息、后续 Cancel、过期、没有区域、跨国的情况都不产生影响；Update 之后只由新消息驱动影响；空索引是一次成功的「没有生效预警」运行；CAP 正文失败时不编造预警。
- **隔离环境 live 探测**：`pnpm test:tmd-cap-live`，即 `scripts/r1-5-tmd-cap-live.ts`。数据库建在 `.tmp/tmd-cap-live-<时间>/isolated.sqlite3`，只访问 TMD 官方入口。结果按三类如实记录：alerts_present（有生效预警）/ no_active_alerts（没有生效预警）/ source_unreachable（源不可达）。
