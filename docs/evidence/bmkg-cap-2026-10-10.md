## 2. 实现（复用 TMD cap_index 路径，未建通用框架）

- `bmkg` 源 `format` 由 `rss` 改为 `cap_index`，`countryCode: "ID"`，`capAreaMatch: "polygon"`，`capIndexLimit: 100`，`capIndexOverflow: "anomaly"`（条目超上限即结构异常，不静默截断）。TMD 行为不变（默认 geocode、20 条截断）。
- 正文白名单 `CAP_BODY_RULES.bmkg`：仅 `https://www.bmkg.go.id` + 路径 `^/alerts/nowcast/en/[A-Za-z0-9]+_alert\.xml$`；与 TMD 同一套检查（凭据、非默认端口、host、`../`/编码伪装、query/fragment、非规范 URL）。正文请求 `redirect: "error"`，并复核 `redirected`/最终 URL。索引中任一非法链接 → 结构异常（源失败），**不当作“无预警”**。
- 生命周期沿用 CAP：只取 `Actual`；Update/Cancel 需 `sent` 可解析且不在未来才撤销/替代；`expires<=now` → expired；缺 `expires` → unknown（不可触发事件）。
- 严重度：Extreme→critical，Severe→warning，Moderate→watch，其余→info（官方原值原样映射）。
- **区域关联**：只用结构化 `<polygon>`：港口目录坐标（仅与发布国同国的港口，Jakarta −6.10, 106.88）落在某个多边形内才关联港口。`areaDesc` 只作 `alertRegion` 展示，**不参与关联**；description 中提到的地名**不算覆盖**。
- 规则输出不变：WR-O01/WR-O02 只产生 `potential`，provenance `system`；官方预警作为 officialBasis。

## 3. 固定样本测试（`server/providers/bmkg-cap.test.ts`，15 例，与 live 分开）

范围：parser → provider → SQLite（sync job）→ panel **服务层**；不是 HTTP 路由，也不是浏览器。合成 CAP 在文件内标明 SYNTHETIC。

- 入口结构（真实样本）：RSS 索引 12 链接全部符合白名单；真实正文 Actual/Alert、Moderate→watch、effective/expires 正确、areaDesc 作 region、无 Jakarta 多边形 → 不关联港口。
- 白名单负例：TMD 链接对 BMKG 拒绝（反之亦然，TMD 规则不变）、http、凭据、端口、他域/伪域、`../`、`%2e`、`/id/` 路径、query、非 `_alert.xml`；索引非法链接 / 超 100 条 → 结构异常；空索引 → `[]`。
- 链路正例：多边形覆盖 Jakarta → officialAlerts 有 bmkg，WR-O01 `potential`/`system`/warning。
- 链路负例：仅正文/areaDesc 提到 Jakarta、Tanjung Priok（多边形在别处）→ 不关联、无影响；缺多边形 → 不关联；跨国多边形（盖住 Laem Chabang）→ 不关联；Test 状态忽略；已过期 → expired；缺 expires → unknown；均无影响。
- 正常无预警：空索引 → 运行 success、0 记录。
- stale：未过期预警从下一轮索引消失 → unknown + stale，不再产生影响。
- 抓取失败：首次失败 → 整轮失败、不写记录（不是“无预警”）；已有记录时失败 → 记录保留为 `failed`/stale，**不当作撤销**（alertState 不变成 expired），不再产生影响。
- 非法正文链接、跨域重定向 → 源失败、不写记录。
