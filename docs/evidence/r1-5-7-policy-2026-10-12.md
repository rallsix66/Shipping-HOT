## 2. 实现
| 项 | 做法 |
|---|---|
| 存储 | 复用两张表；新增迁移 **017**（015/016 没有改动）：record 加 `source_type`、`body_excerpt`、`full_text`、`basis_text`、`stage`、`is_fixture`、`supersedes_policy_id`/`superseded_by_policy_id`/`relation_kind`；version 加 `snapshot_json`（该版本全部字段的完整快照）和 `entered_by`；新建只追加的 `policy_change_log` |
| 录入规则 | 必填：录入人、https 来源链接、依据说明。🏛 官方（政府公告）必须存全文副本；📰 平台规则只存摘录 + 链接，提交全文会被拒；只有媒体报道的只能录为「传闻」，传闻也不能挂官方/平台来源。日期必须是真实日历日，发布日 ≤ 生效日 ≤ 失效日；「已发布待生效」必须填生效日；生效日未到时不能直接录成「已生效」；「已修订/已废止」不能直接录入，只能通过显式操作得到 |
| 版本 | 修订会新增一个版本（必须写变更说明）；旧版本内容从不改写，只补一个「被哪个版本取代」的链接；旧版本的依据、全文、摘录都保存在快照里 |
| 替代/废止 | 新建时带 `supersedesPolicyId` + `relation`（revised/repealed）：旧记录追加一个「已修订/已废止」版本，两条记录互相关联，旧依据保留。也可以无替代直接废止（必填录入人、原因和 https 依据；废止依据只记在新版本上，记录原来的来源不变）。已修订/已废止的记录不能再修订或被替代；fixture 不能被真实记录替代；fixture 标记创建后不能更改 |
| 生效切换 | 判断日 = 当前时间换算到 UTC+8 的日历日，生效日当天 00:00（UTC+8）起算已生效，失效日当天仍算有效。只有「已发布待生效」会在生效日自动显示为已生效（⚙）；传闻、征求意见、已修订、已废止到日子也不会自动生效。时钟用 `TEST_NOW`，**只有同时设置 `SHIPPING_TEST_CLOCK=1` 才生效**，接口返回中标明用的是测试时钟还是系统时钟。自动生效是读取时计算出来的，不会改写存储的状态 |
| 查询/导出 | `GET /api/shipping/policies` 可按国家、平台、类别、当前状态、生效日区间和关键词筛选；`GET /api/shipping/policies/:id` 返回记录、全部版本快照和变更记录；`GET /api/shipping/policies/export` 用同一套筛选参数导出 CSV（带 BOM，防公式注入）。GET 都只查询 |
| 写入 | 只有三个显式 POST：`/api/shipping/policies`（新建/替代）、`/:id/revise`、`/:id/repeal` |
| 页面 | 新增 `/policies`（导航「政策库」）：筛选、列表、导出链接、详情（全文/摘录、依据、来源、录入人、替代关系、版本、变更记录）、录入/修订表单、废止。`/calendar` 新增「政策生效日」图层，独立开关、默认关闭，与假日和大促分开，标注「参考，非停工事实」 |
